02 · Private 후보군: 세 묶음을 합치기

클릭한 기사 전부, 최대 24개의 retained-trace non-click, 별도로 선택한 추가 weak negative를 합칩니다. 세 묶음은 중복되지 않습니다.

추가 예산 B = min(24, max(4, 4 × 양성 수))
실제 추가 수 = min(K, B)
총 후보 수 = 양성 수 + min(적격 trace non-click 수, 24) + 실제 추가 수

직접 계산: 24개와 16개는 왜 함께 들어갈까?

세 묶음은 서로 중복되지 않습니다. 아래 수를 바꾸면 각각의 상한과 최종 입력 크기가 바뀝니다.

교육용 계산기입니다. 실제 기사 선택·날짜 조건·모델 실행을 수행하지 않습니다. 양성 기사가 있는 query를 가정합니다.

4 + 24 + 16 = 44에서 24는 기존 trace에서 실제로 포함한 기사 수이고, 16은 다른 추가 후보 집합에서 새로 선택한 기사 수입니다. “24개 중 16개를 골랐는데 둘 다 더하는 것”이 아닙니다.

조건추가 후보의 범위선택의 의미
Recent-window당일 및 앞선 3일해당 기간에서 추가 기사를 표본 추출
Same-day expansion당일동결된 클릭 수로 정렬하고 동점은 원천 파일 순서 사용

Same-day의 선택 규칙이 hard negative나 실제 인기 기사를 보장하지는 않습니다. 타깃 날짜의 클릭을 이용해 양성을 정한 retrospective 평가 후보군이며, 클릭 전에 똑같이 만들 수 있는 온라인 후보군이라는 주장은 아닙니다.

05 · MIND는 출발 데이터부터 다릅니다

MIND는 독립적으로 진술한 프로필 대신 클릭 이력과 impression slate를 제공합니다. 따라서 public P는 명시적 프로필이 아니라 history-derived proxy입니다. Private의 25개 열을 그대로 가져오는 실험이 아닙니다.

가상의 behavior 기록이력 H1 H2 H3 · 원래 slate A-1 B-0 C-0
원래 slate 유지A는 양성, B/C는 비클릭. 세 후보 모두 E=1.
새 기사 10개 추가훈련에서 만든 popular pool에서 원래 slate와 이력을 제외하고 선택. 추가 후보는 E=0, 할당 label=0.
모든 후보를 같은 scorer로 평가후보 순서 자체는 섞고, 원래 위치나 reciprocal rank는 입력하지 않습니다.

위 A/B/C는 설명용 ID입니다. 실제 프로토콜은 훈련 impression 60,000개를 chronological 51,000/9,000으로 나누고, 선택 후 전체 60,000개로 refit해 development 30,000개에서 평가합니다. 선택 단계의 통계·pool은 fitting partition만 사용하고, refit 단계에서 전체 training으로 다시 구성합니다.

이력은 최대 30개 클릭을 사용합니다. Private의 “최대 24 + 추가 예산” 규칙과 MIND의 “원래 slate + 추가 10개” 규칙을 혼합하지 마세요.

07 · public P와 C가 같은 이력에서 나오는 이유

단위 후보 벡터 v와 단위 이력 벡터들의 평균 h̄를 생각해 봅시다.

p = vᵀh̄ / ‖h̄‖₂
C_mean = meanⱼ(vᵀhⱼ) = vᵀh̄
따라서 C_mean = ‖h̄‖₂ × p

같은 순위, 다른 크기: public p와 C_mean

후보 A/B/C의 p를 0.8 / 0.5 / 0.2로 고정하고, 이력 평균 벡터의 노름을 바꿔보세요.

단위 이력 벡터와 단위 후보 벡터를 가정한 수학 예시입니다. r=0에서는 정규화된 p의 식이 정의되지 않으므로 이 데모에서 제외합니다. 빈 이력 처리는 실제 구현 규약을 따릅니다.

한 query에서는 ‖h̄‖₂가 모든 후보에 공통인 양수이므로 두 필드의 후보 순서는 같습니다. 서로 다른 query에서는 이 배율이 달라질 수 있습니다. 따라서 숫자는 항상 같지 않지만 독립적인 두 semantic evidence source도 아닙니다.

여기서 public C attention은 cosine 기반 요약입니다. Private의 날짜 감쇠 요약을 public 정의에 그대로 대입하지 마세요.

09 · 점수에서 순위와 지표로

모델은 각 후보 행에 score를 매기고, 같은 query 안에서 내림차순 정렬합니다. Private headline의 ExtraTrees class-1 probability는 ranking score로 사용하며 calibrated CTR이라고 해석하지 않습니다.

같은 기사라도 순서를 바꾸면 지표가 달라집니다

양성 기사 A·C와 음성 기사 B·D·E를 가정합니다. 순위의 label을 직접 입력하세요.

이 데모는 한 query의 NDCG@k·Recall@k·reciprocal rank를 계산합니다. 논문의 NDCG@10 결과가 아니며, MRR은 여러 query의 reciprocal rank 평균입니다.

DCG@k = Σᵣ₌₁ᵏ labelᵣ / log₂(r+1)
NDCG@k = DCG@k / IDCG@k
Recall@k = top-k 양성 수 / 전체 양성 수
Reciprocal rank = 1 / 첫 양성 순위

한 사용자가 여러 query를 가질 수 있으므로 불확실성은 행을 독립적으로 뽑는 것이 아니라 user 단위로 묶어 평가합니다. Paired 비교는 두 모델에 같은 후보 행을 사용합니다.
